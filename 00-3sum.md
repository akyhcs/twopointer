Absolutely. Since you've already understood **why sorting is needed**, let's compare the **brute force** and the **optimized solution** side by side. I'll explain every change.

---

# 1. Brute Force (O(n³))

This is probably similar to what you wrote.

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {

        List<List<Integer>> result = new ArrayList<>();
        Set<List<Integer>> set = new HashSet<>();

        int n = nums.length;

        for (int i = 0; i < n - 2; i++) {

            for (int j = i + 1; j < n - 1; j++) {

                for (int k = j + 1; k < n; k++) {

                    if (nums[i] + nums[j] + nums[k] == 0) {

                        List<Integer> triplet = Arrays.asList(nums[i], nums[j], nums[k]);

                        Collections.sort(triplet);      // Normalize order

                        set.add(triplet);               // Remove duplicates
                    }
                }
            }
        }

        result.addAll(set);
        return result;
    }
}
```

### Complexity

```
Outer loop      -> O(n)
Middle loop     -> O(n)
Inner loop      -> O(n)

Total = O(n³)
```

For `n = 3000`, this is too slow.

---

# 2. Optimized Solution (O(n²))

Now notice the changes carefully.

```java
class Solution {

    public List<List<Integer>> threeSum(int[] nums) {

        List<List<Integer>> result = new ArrayList<>();

        Arrays.sort(nums);                     // Step 1

        for (int i = 0; i < nums.length - 2; i++) {

            if (i > 0 && nums[i] == nums[i - 1])
                continue;                      // Step 2

            int left = i + 1;                  // Step 3
            int right = nums.length - 1;

            while (left < right) {

                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {

                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));

                    left++;
                    right--;

                    while (left < right && nums[left] == nums[left - 1])
                        left++;

                    while (left < right && nums[right] == nums[right + 1])
                        right--;

                }

                else if (sum < 0) {

                    left++;

                }

                else {

                    right--;

                }
            }
        }

        return result;
    }
}
```

# Let's compare line by line

## Brute Force

```
for(i)

    for(j)

        for(k)
```

Three loops.

---

## Optimized

```
for(i)

    left = i + 1
    right = n - 1

    while(left < right)
```

Only **one loop** and **one while loop**.

We completely removed the third nested loop.

---

## Why does this work?

Suppose after sorting we have

```
-4 -1 -1 0 1 2
```

Fix

```
i

↓

-4
```

Now

```
left  = -1
right = 2
```

```
-4 + (-1) + 2 = -3
```

Too small.

Instead of checking every possible third element...

We already know:

> **To increase the sum, move `left` right.**

```
-4 -1 -1 0 1 2
       L       R
```

Again

```
-4 + (-1) + 2 = -3
```

Still too small.

Move `left`.

```
-4 -1 -1 0 1 2
          L    R
```

```
-4 + 0 + 2 = -2
```

Still too small.

Move `left`.

Notice something?

We never went back.

Each pointer only moves in one direction.

That's why the `while` loop is **O(n)**.

# Why skip duplicates?

Imagine the sorted array

```
[-1, -1, -1, 2]
```

Without this line

```java
if(i > 0 && nums[i] == nums[i-1])
    continue;
```

You'll start from

```
i = first -1
```

and later again

```
i = second -1
```

Both searches would produce the same triplet.

So we skip repeated starting values.

---

After finding one valid triplet, suppose the array looks like

```
-1  -1   0   1   1
     L       R
```

If we simply do

```java
left++;
right--;
```

we may land on the same value again and generate duplicate triplets.

That's why we skip duplicate values:

```java
while(left < right && nums[left] == nums[left-1])
    left++;

while(left < right && nums[right] == nums[right+1])
    right--;
```

```

```
